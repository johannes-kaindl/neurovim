# Conformance vectors

Generated by `npm run build:conformance` from the TypeScript core — do not edit by hand. Each `<function>.json` holds `{ schema, function, cases: [{ name, args, expected }] }`; `expected` is what the TS core returns for `args`. A consumer that re-implements a rule in another language (the Lua port in `neurovim.nvim`) vendors these files and must pass every case. A rule change here changes the vectors, so a lagging port fails visibly. `null` in `args` means "not set".

`getDiff` and `getDivergentLines` align lines along a longest common subsequence, and a port must align exactly the same way: match the common prefix and suffix first, then walk a suffix-LCS table over the middle from the top; when the current lines match, keep both; otherwise drop the current line if `L[i+1][j] >= L[i][j+1]`, else add the solution line. `lines_off = max(n, m) − LCS`. `getDivergentLines` marks every dropped line and, for each run of added lines that borders no dropped line, the line at its insertion point, clamped to the last line (nothing for an empty text). The vectors `tie: drop before add` and `changed first line before an equal line` fail a port that breaks ties the other way or skips the prefix/suffix step.
